# 退出、入仓、出售与重试

本文维护退出到结算仓库、入仓核验、仓库出售、返回入口和失败后的整体重试。

## 退出与结算提示

退出到仓库依次执行：打开暂停菜单、点击退出、确认退出、等待结算、处理提示并确认仓库。结算点「继续」之后，仓库可能先短暂显示，再被拟态单质失活提示覆盖。因此提示检查与仓库等待由 `BagelWaitWarehouse` 在同一循环处理，不能在单帧未发现提示时永久跳过。

每轮先检查截图时间，再按以下顺序处理画面：

| 条件 | 操作与完成判据 |
| --- | --- |
| 截图时间未递增 | 等待新截图，不点击，也不增加仓库计数 |
| 完整失活标题命中 | 清零仓库计数；识别该提示的「确认」，按文字中心点击。按钮暂不可见或点击失败时继续观察 |
| 标题未命中，且「放入仓库」「返回研究站」同时命中 | 累计仓库帧。连续至少三张新截图、跨度至少一秒，才确认到仓库 |
| 其他画面或暂停 | 清零仓库计数，重新等待 |

标题区域匹配完整说明「带出的拟态单质已失活，转化为惰性单质」，文字匹配阈值为 0.90。等待间隔为 0.5 秒。提示处理与仓库确认共用 30 秒上限，超时失败并保存现场；区域配置缺失等程序错误直接失败。

正常退出、失败收尾、直接从提示页启动退出操作及首次启动恢复共用该等待操作。入仓首次核对和点击后的核验也检查迟到提示。关闭提示后，操作重读仓库：

- 尚未发送入仓点击时，重新建立数量基线。
- 已发送入仓点击时，保留原基线，继续核对物资去向。

提示确认不增加入仓或成功次数。入仓自身仍受原有节点和操作时限约束，不因提示重置预算。

**适用限制。** 提示出现与点击响应的实际时序，以及提示关闭后的完整自动结算行为仍待核对。

单件物品在重拖预算内搬不动不算这类拖拽错误：它是游戏拒绝搬运（金币）或物品没抓到，按[拖拽时序](container.md#拖拽时序)跳过该格继续装别的，不影响面板状态判断；连续两件搬不动则按同节报局内流程失败，与这里一样走退出本局重开。

## 入仓核验

点击「放入仓库」后，操作同时核对安全箱和仓库占用。仓库「全部 N/M」中的 N 表示占用，M 表示当前界面显示的实际容量。M 不能固定取 280。下表中的占用变化均与点击前读数比较。

| 结果 | 判定与处理 |
| --- | --- |
| 安全箱清空，N 增加 | 入仓成功。包括占用从 `(M−1)/M` 增至 `M/M`，恰好满仓的情况 |
| 安全箱清空，N 不变，且 N<M | 入仓成功。允许物品合并到已有堆叠 |
| 安全箱清空，N 不变，且 N≥M | 正式结算允许满仓合并堆叠；独立入仓工具仍保留原保护 |
| 安全箱清空，但 N 下降或必要读数无法核对 | 停止，不计入仓成功 |
| 安全箱只减少部分格子 | 正式结算交给一次出售后再入仓；独立入仓工具仍停止 |
| 安全箱格子完全未变 | 允许有限重试或判满仓 |
| 安全箱仍占用，且 N≥M 连续 6 帧 | 记为仓满并停止 |

正式结算的满仓或残留处理见[出售间隔与残留处理](#出售间隔与入仓重试)。独立入仓、独立清理工具默认仍保留原保护。入仓核验不按物品名称判断。

入仓成功后，正式应用按清理开关处理仓库，再执行[出售与结算核验](#出售与结算核验)。安全箱为空且容量可读即可结束结算并返回入口；仓库已满不再阻断。入仓后恰好满仓时，正式应用仍可按现有清理规则提前出售一次。

## 仓库清理与返回

### 出售方案

清理开关默认开启。关闭时，正式应用只执行入仓。出售按以下方案选择：

| 方案 | 类型 | 品质 |
| --- | --- | --- |
| 默认第 1 步 | 贵重物品、战术棱镜 | C/B/A/S |
| 默认第 2 步 | 其他 | C/B/A |
| 自定义 | 按 `clean_steps` 从上到下，每一步使用该步选择的类型，不能为空 | 每一步使用该步选择的品质，不能为空 |

默认方案保留 S 品质「其他」，包括金色蓝图和 S 品质材料；同时保留全部 Z 品质、装备、战术道具和门禁卡。两步必须分别执行，不能合并类型和品质后出售，否则会重新包含「其他 × S」。它按游戏筛选分类保留物品，不逐件识别蓝图，也不按名称、重复数量或解锁状态判断。

配置、设置页和启动恢复共用同一份默认步骤。默认模式直接使用这两步，不改写已有 `clean_steps`；自定义模式仍按已保存的步骤执行。显式传入的空步骤组保持为空，不能回退到默认出售。单步出售操作必须显式接收筛选范围，调用者负责执行完整方案。

全部筛选按钮独立于默认方案定义。每一步先取消范围外的选项，再补选目标项；第 2 步必须取消 S 品质及第 1 步的类型。两步实际筛选范围、连续出售和返回仓库的完整实机流程尚未验收。

快速选择中，同一步的类型和品质必须同时匹配，物品才会进入这一步的出售范围。「全部」始终不选。一次结算内按步骤顺序各打开一次快速选择。有物品的步骤必须点完确认出售、确认弹窗并回到仓库，才开始下一步。没有命中物品时取消出售并回到仓库，也才开始下一步。任一步失败或确认未完成就停止，不继续后面的步骤，也不再入仓。操作每次重新读取所有选项，并取消该步未选的项目。清理流程不点击整理，也不自动转化货币。

**空箱结算只跳过出售。** 入仓操作确认安全箱原本为空时，清理节点跳过出售，但继续执行末尾的安全箱和仓库容量核验；不能直接结束结算。空箱时不清理已有库存，与清理开关和出售方案无关，正常局和失败收尾均适用。核验通过后仍返回原有空箱状态，沿用现有成功、空箱及失败计数规则。

### 出售与结算核验

出售间隔、提前出售、残留再入仓和最终核验均见[出售与入仓重试](#出售间隔与入仓重试)。本节只维护出售筛选方案和返回操作。

**返回入口。** 正常各局从结算仓库直接返回贝果主界面，不经过达塔对话。返回操作报告实际落点，后续入场按[快捷手册入口规则](entry.md#快捷手册入口与局间返回)处理。黑屏和入口渐显期间继续等待；恢复触发条件和时限见[整体重试说明](#页面阻挡恢复)。页面恢复不改变任务计数或首次清空资格。

**返回时的奖励提示。** 结算仓库点击「返回研究站」后，若同时识别到「撤离奖励提示」和奖励转移说明，返回操作只确认 1 次，再等待完整贝果主界面或大世界 HUD。

### 筛选与出售等待

筛选每次只点击一个选项，不叠加内外两层固定等待。点击后每 0.25 秒回读；保留待核对的选项和目标状态，最多等 3 秒。未生效或状态始终不清晰则停止，不再次翻转该选项。

出售获得提示只点击一次。操作不在点击函数内固定等待，外部每 0.5 秒观察一次，节点上限为 20 秒。保留安全箱、筛选、件数、出售预览和仓库占用核验。

## 出售间隔与入仓重试

应用按本次任务内非空且完整入仓的次数累计出售间隔，失败局带回物资也计入；空箱、未支持出生点和启动遗留物资不计入。默认间隔见[配置表](overview.md#配置bagelconfig)，范围1–999；关闭自动清理时不出售。新任务归零，暂停和局内失败重开不归零。

每次结算创建独立操作，计数必须由应用持有。结算接收本次是否到期的决定，完成出售流程（包括筛选0件并正常取消）后通过结果数据告知应用清零。只在结算最终核验通过后更新计数，不能因筛选失败提前清零。

正常达到成功局数上限的最后一个非空局补卖，即使未到间隔。同一结算只进入一次清理：默认方案按顺序卖完两步，自定义方案按保存顺序卖完全部步骤，中间不再入仓。全部步骤完成后才报告出售完成；不能在第 1 步结束时清零计数。筛选范围见[出售方案](#出售方案)。手动停止和异常结束不追加补卖，失败局仍按正常间隔处理。空箱只核验，不因到期或结束标志而出售。

首次入仓后有残留，或完整入仓后仓库已满时，允许在自动清理开启的前提下提前出售。出售仍使用用户的类型和品质筛选，范围包含已有库存；该操作也可能出售安全箱内符合筛选的物品。只对状态明确的安全箱执行，未知不当作空。

残留处理顺序：首次入仓 → 按方案顺序卖完各步 → 再点击入仓一次 → 核验安全箱和仓库容量。第二次入仓后仍有物资或状态不明，停止并保留现场，不循环出售或反复入仓。安全箱明确为空且容量可读时，即使仓库已满，也允许结算成功并返回下一局。常规完整入仓后出售不需要额外重试入仓。

### 最终核验

结算成功必须同时看到仓库主界面、安全箱为空和可读容量。原本空箱、关闭清理和出售后再入仓都执行此核验。满仓本身不构成失败。

- 正式结算允许满仓合并堆叠后安全箱清空、仓库占用不变；占用下降或读数未知则停止。
- 允许残留出售时，仓库占用或安全箱占用必须减少。不能出现新增安全箱占用格。后续结算仍须清空残留。
- 独立入仓工具保留满仓堆叠保护。独立出售工具默认要求安全箱为空，只有正式结算允许残留出售。

启动恢复复用同一结算操作，但不按间隔主动出售；仅在满仓或残留时尝试出售腾位，不改变本次任务的计数。恢复入口行为由对应启动恢复流程负责。

### 验证边界

离线测试覆盖满仓、残留、未知容量和筛选 0 件后取消，范围见[验证现状](README.md#验证现状)。这些分支尚未完成实机验证。失败局非空入仓及手动停止不补卖也尚未完成实机验证。

间隔出售和结束补卖缺少已归档的连续验收证据。实机验收必须核对入仓、计数、实际出售范围及最终返回结果，不能仅以启动运行作为完成依据。

## 整体重试

### 次数与适用范围

“整体重试次数”（`max_failure_retries`）表示正式应用因局内失败最多额外入场多少次。默认值和取值范围见[贝果配置表](overview.md#配置bagelconfig)。设置页显示的是累计失败上限，与内部重开次数的换算由 `bagel/gui/setting_interface.py` 实现；日志和运行记录仍使用内部重开次数。

以下情况不消耗整体重试次数：

- 首次入场。
- 成功后的下一局。
- 非支持出生点的重选。
- 容器局部恢复成功。

新任务开始时，正式应用初始化已用整体重试次数。成功入仓、重建子操作、暂停和恢复均不清零。共用的局内执行器和开发试跑只返回当前结果，不自动结算或开启下一局。

完成失败收尾和返回后，正式应用在准备额外入场时，增加已用整体重试次数。额外入场失败时，正式应用停止运行。已用整体重试次数不退回。

日志和运行记录保存失败原因、已用整体重试次数、配置上限和停止原因。

### 失败收尾

寻路卡位、定位失败、被敌人击杀、局内节点或操作超时、容器恢复失败，以及搜查或解锁中断，均进入以下流程：

1. 释放本流程持有的前进、交互和拖拽输入。
2. 记录原始失败原因和截图。
3. 读取新画面，根据当前状态执行局内退出、死亡结算或仓库核验。
4. 核对安全箱物资已入仓。
5. 按[仓库清理规则](#仓库清理与返回)处理：有物入仓按[出售间隔与残留处理](#出售间隔与入仓重试)累计，失败终止不补卖，空箱只跳过出售；末尾安全箱和仓库容量核验始终执行。
6. 完成仓库结算后，比较已用整体重试次数与配置上限。

整体重试次数耗尽时，正式应用停在仓库。仍有可用次数时，正式应用返回入口，再开始一次额外入场。失败局不增加成功局数，也不改变连续空箱次数。

退出、入仓、清理或返回失败时，正式应用在当前画面停止。日志同时报告原始失败和收尾失败。正常收集流程末尾的退出失败也直接停止。

业务操作显式标记可恢复失败。实际节点或操作超时使用框架的超时状态。人工结束、初始化失败、资源或配置缺失，以及程序异常，均直接停止。安全箱格子持续未知、开放格变化或无法核对拖拽目标时也直接停止并保留现场，不自动退出重开。正式应用不会根据错误文字将这些结果改写成可恢复超时。

### 页面阻挡恢复

正式入场遇到未识别画面，且未发现战斗常驻界面（HUD）时，入场操作调用通用返回大世界流程。返回后，操作读取新画面并重新检查入场条件。独立入场工具默认不启用此恢复。

仓库返回操作等待完整贝果主界面或普通大世界 HUD，最多 25 秒。加载期间的黑屏和单帧漏识别不触发恢复，也不发送点击。返回箭头也会先于入口内容出现，不能仅凭箭头提前恢复。仅在该等待超时后调用通用返回大世界流程。

返回操作识别主界面后报告“已返回贝果入口”；识别普通大世界或完成通用恢复后报告“已返回大世界”，不再寻找达塔。正常后续轮次直接复用主界面；大世界落点由下一次入场重新准备[快捷手册入口](entry.md#快捷手册入口与局间返回)。

| 所属操作 | 最多恢复次数 | 恢复最长时间 |
| --- | --- | --- |
| 每次入场操作 | 1 次 | 30 秒 |
| 每次仓库返回操作 | 1 次 | 20 秒 |

两种恢复还受所属操作的剩余有效时间限制。通用返回失败，或恢复后仍不能继续时，当前操作停止并保留现场。

贝果复用通用返回流程中的识别与点击，不增加签到页专用逻辑。页面恢复不消耗整体重试次数，也不重置首次清空资格或任务计数。

### 验证范围

离线回归主要执行正式应用的完整节点链，检查以下结果：

- 额外入场次数。
- 结算顺序。
- 成功局数。
- 最终画面。
- 原始错误。

配置持久化和设置范围另行检查。这些离线测试位于测试仓，测的是内置版本，见[验证现状](README.md#验证现状)。页面阻挡测试使用测试仓归档的 `screens/画面-通用/贝果返回阻挡页.webp`。

返回回归使用连续过渡画面，检查正常返回后继续入场时不调用地图传送，并保留页面阻挡和恢复超时的代表场景。当前测试不逐项展开所有加载与恢复组合，覆盖范围见[验证现状](README.md#验证现状)。

实机验收需要在 1080p 识别基准下，分别核对录像店和白鸽工地路线的正常返回与后续入场。完整失败收尾及其后的额外入场、超时恢复、撤离奖励提示和实际页面阻挡尚未完成完整实机验证。默认仓库清理策略下的离线结果不能代替这些验收。

通用恢复的左上入口仅接受完整的“街区”“勘域”“区域”文字，不使用单个“区”或“域”匹配。贝果入口渐显期间不点击返回；真正的阻挡页在等待超时后仍使用一次、有时限的通用恢复。

入口渐显的离线样本由稳定入口截图遮挡合成，覆盖仅返回箭头、仅标题与完整入口的顺序。这验证了过早恢复的代码路径，不代表已取得真实动画序列或完成实机验收。真实入口渐显故障的对应截图尚未归档。

### 为什么不用全屏稳定检测

返回入口等待标题与「前往空洞」同时出现。只有返回箭头时继续观察，并受节点时限约束。

不完整页面也可能连续静止，像素稳定不能证明入口完整。通用画面路由的切换防抖依赖自身发起的切换，不能代替结算后的入口识别。搜查面板和转存的稳定检查分别绑定各自业务区域，不能直接复用到研究站。

因此这里使用有时限的完整入口特征等待。通用返回只接受完整文字，避免把「迷宫诡域」中的单字当作返回入口。
