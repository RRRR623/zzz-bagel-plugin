# 入场

本文维护从启动到进入雅努斯高危的规则：首次启动恢复、启动清空、快捷手册入口、选图、入场提示、携带与投资核验。

## 首次启动恢复

恢复只在本任务第一次入场前执行。

- 失败结算识别 DEFEAT，不核对地图名称。
- 退出确认必须包含仅保留安全箱的专用提示。
- 拟态单质失活提示通过完整标题识别，复用[结算仓库等待](settle.md#退出与结算提示)确认后继续转存。
- 仓库处于出售状态时停止。未知页面仅允许既有[页面阻挡恢复](settle.md#页面阻挡恢复)，仍无法识别时停止。

正在进行的局内识别普通攻击按钮和计时后，复用正常退出流程，不打开大地图查询，也不核对地图名称。已打开的大地图通过图例识别，先关闭再识别局内画面。明确的贝果搜查面板先关闭，再识别局内画面。正常退出仍须识别仅保留安全箱的专用提示。

退出遗留局会丢弃安全箱外的物资，不续原路线。退出操作完成后重新截图，再处理启动仓库，不能拿旧结算帧继续判断入口。

启动转存同时核对背包、安全箱和仓库容量；不增加成功次数、出售间隔或失败重试。普通转存不主动出售，满仓或残留按[一次出售再入仓](settle.md#出售间隔与入仓重试)处理，使用应用实际清理开关和筛选。携带物已清空且容量可读时，满仓也允许继续；有残留但清理关闭、未知容量或再入仓后仍残留则停止。

完成遗留局退出和仓库转存后，正式任务再[准备快捷手册入口](#快捷手册入口与局间返回)。返回大世界或贝果页面均需完成首次入口准备，不能沿用来源不明的入场路径。

保留原入场的清空装备、零携带、零投资与首次资格保护。暂停不重新获得启动恢复资格。

离线测试使用真实节点图与归档截图，覆盖范围见[验证现状](README.md#验证现状)。离线画面切换不能证明游戏接受了输入。

非空遗留转存、已有失败页或退出框起点、搜查面板和大地图起点尚未完成实机验证。局内起点和空遗留物资恢复缺少已归档的连续验收证据，不能据此认定所有恢复分支已通过。

## 启动时清空携带物

正式应用每次启动只在第一次入场前允许清空携带物。清空包括背包、安全箱和已装备物品，不更换代理人。独立入场工具默认只核验，不自动卸装。

### 资格与起点

首次调用入场操作前，应用即消耗清空资格。出生检查次数不能代替这项资格。暂停、恢复、失败重开和节点重试均不恢复资格；停止任务后重新启动才重新初始化。

| 当前状态 | 操作 |
| --- | --- |
| 备战已装备槽全空，背包和安全箱零占用 | 不搬运，继续原有入场核验 |
| 备战背包和安全箱为空，但仍有装备 | 跳过仓库往返，逐格卸下已装备物品 |
| 备战背包或安全箱有物品 | 先打开仓库转存内容物，检查余量，再返回备战卸装 |
| 首次从贝果仓库启动 | 按[首次启动恢复](#首次启动恢复)转存遗留物，返回入口后重新选图 |
| 读数缺失或非法 | 限次读取，不当作空容器 |
| 后续局仍有携带物 | 停止并保留现场 |

零携带要求10个已装备槽全空，且背包和安全箱零占用。容器读数或槽位状态不明时，最多读取5帧，期间不搬运。读取规则见[携带读取](#携带读取)。

仓库只核验可见数量。返回备战后核验槽位和容器，卸装结束时全部槽位为空且容器零占用。

### 仓库转存

仅在仓库主画面明确，背包、安全箱及仓库数量可读时，点击「放入仓库」。启动入口、返回节点和每轮转存都先排除出售底栏、快速选择、出售预览和获得硬币弹窗。出现出售状态时停止，不转存、不确认、不返回；空箱也不能越过此检查。

普通背包只通过文字识别（OCR）读取占用数和容量，例如`0/15`表示背包为空、容量为15，不再定位格子或检查格子内是否有物品。固定区域读数失败时，只接受左侧唯一背包标题所在行的完整数量；读数缺失、非法或存在多个候选时返回未知。活动背包不参与普通背包占用核验。

安全箱没有对应的占用数字，仍按已有格子状态识别占用、空闲和锁定格。点击前与结果确认时，连续两帧必须同时满足：

- 普通背包和仓库的占用数、容量一致。
- 安全箱的格子状态一致。

缺失或非法读数、安全箱状态未知，或者离开仓库主画面时，清除稳定记录并限次重读。普通背包连续两帧读到零占用后按空包处理，不再用格子图像否决该结果。

转存完成要求背包和安全箱全部清空、容量不变且仓库占用不下降。合并堆叠后，仓库占用可以不变。

点击「放入仓库」后，若携带数量未变且仓库仍有空位，只继续核验，不重复点击。达到[核验上限](#重试暂停与停止)仍未确认结果时停止，不报告满仓，也不进入出售流程。

独立转存只完成部分物资时，程序记录已转出数量并停止。正式启动流程的满仓、残留和一次出售重试见[出售与入仓重试](settle.md#出售间隔与入仓重试)。启动转存不按间隔主动出售，也不增加任务计数。

### 备战卸装

依次检查 3 个代理人武备槽、3 格队伍装备和 4 格道具。仅双击明确占用的槽位；空槽跳过，未知槽重新识别。代理人头像、替换角色按钮和左侧仓储候选列表都不是卸装目标。

背包内容清空后才卸背包装备。仅此槽位允许背包容量下降，其他槽位要求容量不变；安全箱容量始终不得改变。

每件物品按以下顺序操作：

1. 确认备战无遮挡，连续两帧核对槽位占用、背包和安全箱数量与容量，等待0.5秒。
2. 点击槽心，按住0.08秒。
3. 松开后等待0.11秒，再向同一槽心点击，按住0.08秒。
4. 等待0.5秒。若出现详情，点击空白处 `(950, 540)` 关闭，每次双击后最多点击2次；清空子操作开始时已有详情也最多关闭2次。
5. 确认无遮挡后，连续两帧核验源槽为空、其他槽位占用未变、两个容器零占用，且容量符合上述规则，再处理下一格。

无遮挡要求「预设组合」「前往空洞」可识别，且备战右侧没有「放入背包」「放入安全箱」「放入仓储枢纽」这些详情操作文字。关闭点击位于候选列表与备战面板之间，不点击详情内的搬运或出售按钮。

稳定判据使用容器数量、容量和槽位占用，不要求图标像素静止。未知槽、缺失读数、详情或非备战画面会清除稳定记录，但保留双击前的基准状态。

点击成功和转存浮字均不算卸装成功。全部10槽为空且容器零占用，连续两帧一致后才结束。返回入场操作后再次核验零携带，通过才允许入场；非零则停止，不循环清空。

### 重试、暂停与停止

核验达到上限后，仅当连续两帧确认原槽仍有物、全部槽位占用及容器数量和容量均未变，才允许重试。每格最多重试3次，连同首次共4次双击；换格时清零。

关闭详情和等待恢复计入本次核验预算。只有实际重试双击才重置该预算。重试耗尽、详情关闭失败或状态异常时停止；状态不明只限次重读，不补发双击。总时限优先，不保证用完每格重试次数。

| 条件 | 行为 |
| --- | --- |
| 点击前等待期间暂停或停止 | 不输入。即使已经恢复，也重新识别后再选择物品 |
| 两次点击之间暂停或停止 | 结束本次卸装，不续发第二次点击 |
| 双击或批量按钮之后暂停恢复 | 只核验结果，不重复输入；卸装详情仍在时不补点空白处 |
| 任一点击返回失败 | 停止，不重试输入 |
| 要转存内容物但仓库已满 | 独立转存停止；正式启动仓库按结算的一次出售重试处理 |
| 内容物转存后，仓位不足以容纳待卸装备 | 停止。按每个占用槽最多一个新仓位保守计算 |
| 两个容器原本为空 | 不专门进入仓库预查，每格仍需核验；未生效按上述上限停止 |

| 预算 | 上限 |
| --- | --- |
| 未知状态 | 5帧，每帧间隔0.5秒 |
| 双击或批量入仓后的核验 | 5秒或10次检查，先达到者为准 |
| 单个批量转存或清空操作 | 180秒 |
| 允许首次清空的入场操作 | 660秒，含恢复、转存、返回、卸装和加载 |
| 仅核验的入场操作 | 240秒 |

时限在轮次之间检查，截图和识别耗时可能使实际停止晚于预算。子操作独立计时；清空不占15秒的零携带检查节点预算。

失败日志应报告阶段、容器或槽位、原因、可读数值、已转存数量和截图名。已经转存的物品不回滚；下次启动只处理剩余携带物。

### 实现与验证边界

`BagelApp` 管理首次资格；`BagelEnter` 核验并调用清空；`BagelClearLoadout` 编排卸装；`BagelStoreCarried` 处理背包和安全箱批量转存。`BagelDeposit` 只处理结算安全箱。共用转存基类管理双击、稳定观察、暂停和失败记录。

按钮和数值复用现有画面区域。前往仓库在「贝果-备战/前往仓库」区域内匹配文字（LCS 0.7）；文字缺失时点击已核对的背包数量区域切回背包视图。装备槽使用1080p槽心；普通背包仅读取标题处的数量。

测试范围见[验证现状](README.md#验证现状)。重试耗尽、暂停中断等异常分支的实机覆盖范围尚未明确；离线分支验证不能证明实际识别和点击效果。

## 快捷手册入口与局间返回

根据实测结果，推测返回位置差异由游戏 3.0 版本前后的逻辑不同导致，原因尚未确认。为确保每局退出后回到贝果主界面，首次入场先传送到「录像店－房间」，再通过快捷手册进入。

即使启动时已在贝果主界面、选图页或备战页，也必须重新传送，因为这些页面无法确定入场前位置。

正式任务首次入场时，程序按以下顺序执行：

1. 按[首次启动恢复](#首次启动恢复)处理遗留局和仓库物资。物资核验通过后，才继续准备入口。
2. 从已支持的画面返回大世界。
3. 传送到「录像店－房间」。传送失败时停止。
4. 打开快捷手册的「作战」页签。
5. 选择「周期征讨」分类。
6. 找到「迷宫诡域」卡片后，只点击该卡片的「前往」。
7. 等待贝果主界面。只有同时识别到贝果标题和「前往空洞」，才继续选图、零携带和零投资核验。

正式应用分别传入是否准备首次入口、是否允许首次清空两个参数。后续入场按以下条件处理：

- 正常返回贝果主界面、选图页或备战页时，程序直接继续，不重复传送。
- 返回大世界时，程序重新传送到「录像店－房间」，再从快捷手册进入。程序不改用达塔对话。

独立入场工具默认从现有贝果页面继续。需要重新传送并打开快捷手册时，调用者必须显式启用入口准备。

入口复用已有组件和素材：

- 地图传送调用 `Transport`，目标与情报板一致：区域为「录像店」，传送点为「房间」。该操作复用 `MapTransport`、通用返回和地图传送点数据。
- 打开作战页调用 `round_by_goto_screen`，复用大世界快捷手册按钮、页签区域与已有画面路由。
- 分类选择调用 `CompendiumChooseCategory`，不另写分类点击逻辑。
- 贝果卡片识别复用「副本列表」「前往列表」，主界面识别复用贝果标题和「前往空洞」。
- 活动页按标题前缀「迷宫诡域」识别。投资页标题「迷宫诡域：贝果计划」前缀相同，靠右上角「关卡有风险，投资需谨慎」（LCS 0.7）排除。

不直接调用 `TransportByCompendium` 完成入场：其副本选择会继续等待通用传送确认，而贝果卡片直接打开主界面。贝果专用操作只补充卡片与按钮对应检查、有限滚动，以及点击后的完整入口等待；不修改其他应用共用的传送行为。

快捷手册路由最多等待 30 秒，分类选择最多 15 秒，卡片查找及点击后等待最多 30 秒。卡片未出现时，最多向下拖动列表 5 次，以查找顶部卡片；看到卡片标题但未看到本卡片的「前往」时停止，不点击下一张卡片。已经点击「前往」后只等待，不重复点击。

仓库返回同时等待贝果主界面或普通大世界，最多 25 秒。主界面识别完整即结束；正常各轮不与达塔交互。若实际返回大世界，则报告实际位置，由后续入场重新准备快捷手册入口。只有等待超时才执行既有的一次通用恢复。撤离奖励提示和物资核验保持不变。

### 实机验证范围

「录像店－房间」的首次入场、局间返回，以及从遗留局、结算仓库、备战仓库和异常页面恢复后的入场，仍需分别实机验收。「录像店－HDD」的实测结果、静态检查和离线回归不能代替上述验收。

## 选图与难度

每局从新截图读取实际选中地图和推荐价值。雅努斯高危已经正确时免点击；已知错误选择调整后重新核验。读数不明只等待，节点最多 15 秒。点击已发出后等待生效，不按观察频率重复点击。打开备战前再次核对两项。

推荐价值和投资金额都先遮掉金币再识别：在区域内定位唯一的金币，金币左侧必须没有白字，再把金币及其左侧涂黑后识别。金币紧贴数字，不遮挡时会多读出字，例如 ppocrv6 把细体字读成 `e258000`、ppocrv5 把粗体字读成 `@258000`。游戏的字体粗细设置会让标题和数字左右移动几像素，所以推荐价值区域从 x=1282 起：细体冒号右边缘在 1278，两种字体的金币都从 1287 起。金币定位失败时读数为空，按读数不明处理。

暂停会撤销入场核验资格。在选图阶段恢复时重新读取画面；备战阶段恢复时返回选图核验；已进入入场确认阶段则停止，要求从入口重新运行，避免沿用暂停前的零携带资格。每次执行重新初始化所有状态。

## 入场提示

每种提示单独识别。点击前等待仅在贝果调用处设为 0.15 秒；点击后每 0.25 秒观察新截图，不追加固定 1 秒等待。观察原提示不消耗失败重试次数。

配置较低的电脑上，弹窗出现和关闭都可能变慢。程序把「慢」当作等待，只在画面确实异常时停止。各情况按以下规则处理：

| 情况 | 处理 |
|---|---|
| 备战页点击「前往空洞」后，还没出现任何提示，仍停在备战页 | 点击 3 秒后补点一次，之后只等待 |
| 同一提示点击确认后仍未消失 | 点击 3 秒后，重新识别仍为同一已知提示且确认按钮存在时，补点一次。首次点击起最多等 15 秒；补点不延长上限 |
| 提示点击确认后，下一个弹窗还没出现（空白过渡帧） | 只等待，不设单独上限，由节点 90 秒超时兜底。空白帧不能代表入场成功 |
| 点击「零投资前往空洞」后投资页仍未消失 | 只等待，不重复点击。点击起最多等 15 秒 |
| 提示已切换后再次出现已确认提示、出现未知提示 | 立即停止 |

补点不会误点弹窗按钮：备战页「前往空洞」的位置与提示框「确认」、投资页按钮均不重叠。局内判据保留。

这些间隔是当前实现参数，适用性需通过实机验证，不代表动画已验证可在该时长内结束。

## 入场与携带核验

先按[首次启动恢复](#首次启动恢复)处理遗留局和物资，再按[快捷手册入口规则](#快捷手册入口与局间返回)准备入口，最后核对地图、难度、携带和投资金额。普通大世界、地图、菜单、快捷手册、普通仓库与达塔对话共用通用返回和地图传送。

音擎仓库和驱动仓库的全局识别失败时，入场操作用完整仓库标题补充识别。区域缺失时跳过该项，不将普通仓库当作贝果结算仓库。地图传送失败时停止。

首次清空资格、读取上限和后续局残留保护只在[启动清空](#启动时清空携带物)维护。入场的选图与暂停规则见[等待规则](#)。

单代理人可以入场，不要求补齐队伍。核实零携带后，程序按关键片段识别已知入场提示，识别成功才点击确认。确认后继续核对其他入场提示和零投资，不跳过地图、携带或投资检查。未知提示仍停止，不点击确认。

识别前，程序删除提示中的空白和标点。一条提示的全部片段都命中，才算识别成功。片段的字按顺序出现在提示中即为命中，中间可以夹有其他文字。五个字及以上的片段允许 OCR 错漏一个字，四个字及以下的片段必须完整。

| 提示 | 游戏原文 | 识别片段 |
|---|---|---|
| 代理人队伍未满编 | 代理人队伍未满编，是否继续出战？ | `队伍未满编` |
| 零装备价值 | 当前装备价值为0，未达到推荐价值258000，将会面临极大挑战，是否继续前往？ | `当前装备价值为0`、`未达到推荐价值` |
| 未装备武备 | 存在未装备武备的代理人，是否直接出战？ | `未装备武备` |
| 未穿戴队伍装备 | 未穿戴队伍装备（异体刃、抗蚀器），是否直接出战？ | `未穿戴队伍装备` |

零装备价值提示中的推荐价值随难度变化，留档的非高危提示显示 72100。程序取提示中最长的数字串：数字串有四位及以上、并且与高危推荐价值相差两位及以上时，按未知提示停止。数字串不足四位时不判断难度，难度以选图页的核验为准。

入场提示按阅读顺序拼接文字识别（OCR）结果。程序先按文字框中心高度排序，再按通用规则将中心高度相差不超过 5 像素的片段合为一行，行内从左到右拼接。这样可避免同一行文字框的轻微高度差颠倒句子。拼接保留全部识别文字，不改变金额和容量的读取方式。

## 携带读取

程序不读取武备、装备和道具的价值，已装备物品只看10个槽位的画面。

- **已装备槽：** 每格取槽心 60×60 的灰度。标准差不低于30且亮像素不低于8%算有物品；P95 在12到80之间且亮像素低于1%算空；其余算未知，未知时重读。
- **背包和安全箱：** 各自读取完整容量区域。占用必须是完整的 `N/M`，零占用只接受 `0/M`；`00/15` 不算空背包。
- **投资金额：** 继续使用独立的颜色过滤和严格零值校验。

槽位判断只看亮度，不读文字。装有物品的槽位尚未在细体下回放，也未实机验收。

## 投资金额归零

识别到投资页后，先在完整金额区域定位唯一金币，并遮挡金币及其左侧，再按区域颜色过滤读取金额。遮挡保留原始输入尺寸，边界随金币位置移动，避免固定裁剪截断长金额。金币缺失、候选不唯一或金币左侧仍有白色数值时，返回未知，不按零放行。

操作读取完整金额后决定动作：

| 读数 | 动作与完成条件 |
| --- | --- |
| 正整数，或带 `K/M` 的正数，如 `500K`、`1.5M` | 点击 MIN。点击成功后等待 1 秒，下一轮重新截图读取金额 |
| 初始金额或复核金额精确为 `0` | 点击「前往空洞」。点击成功后，才记录投资已确认 |
| 空值、`O`、`00` 等不明确读数 | 只重新读取，不发送输入 |

点击 MIN 成功不表示金额已归零。非零归零和读数不明共用 3 次重试预算。MIN 未识别或点击失败也消耗 1 次。预算耗尽后，操作再读 1 帧。金额仍不是 `0` 时，操作停止并保存现场。

投资重试预算单独记录，避免节点等待重置框架重试次数。重复执行时，预算清零。点击入场后，操作不重复归零或确认。

## 测试与实机观察

测试使用独立测试仓的 FixtureController，即根据模拟输入切换截图的控制器。完整入场验证前置流程，短流程验证部分失败条件；零携带、零投资和出售保护的具体范围见[验证现状](README.md#验证现状)。当前回归不逐项验证所有提示顺序和重复执行组合。

离线测试验证输入次数、画面顺序和停止边界。实机观察应分别记录选图、入场提示和清理耗时；与旧日志比较时注明条件差异。未触发的场景不能视为已验证。
