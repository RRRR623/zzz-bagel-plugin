# 流程总览

本文维护正式任务的整体流程、配置字段与执行清理。各阶段的细节按 [README](README.md) 的索引查找。

## 脚本流程

`BagelApp` 从已识别且允许启动的画面进入贝果主界面，循环执行到成功次数上限。默认上限为 1，设置为 0 时不限制成功次数。

1. 校验配置和路线开启选择。开启选择无效，或没有任何出生点开启路线时，任务不开始。规则见[贝果路线与出生点](routes.md#开启选择)。
2. 首次启动时若在贝果仓库，先转存携带物，再返回上一页。该转存不主动出售；满仓或残留按一次出售重试处理，不增加任务计数。随后按[快捷手册入口规则](entry.md#快捷手册入口与局间返回)准备首次入场；正常后续轮次复用贝果主界面。各起点的处理规则见[入场与携带核验](entry.md#入场与携带核验)。
3. 按配置选择并核对雅努斯难度，默认高危，进入备战页。
4. 核对当前画面的零携带状态。首次入场可以先清空非零携带，再复核零携带。后续各局发现非零携带时停止。
5. 高危核对零投资后入场。困难和常规不要求投资确认；出现投资页时仍先归零。
6. 用小地图识别出生点，执行该出生点开启的路线，按游标顺序推进。识别规则见[出生识别与导航](navigation.md#出生识别与导航)。
7. 主动退出到仓库（结算后若弹出拟态单质提示，先点确认，见[退出与结算提示](settle.md#退出与结算提示)），核对安全箱物资入仓，再按清理开关处理仓库。
8. 核对结算结果，更新成功局数，决定结束任务或开始下一局。

正常完成链为「执行局内流程 → 正常局退出 → 结算仓库 → 成功局返回入口」。只有路线执行器明确返回「路线走完」，才能进入正常局退出；其它成功状态按提前结束处理，不计成功。正常局退出先释放输入，再调用退出操作确认到达结算仓库；退出失败时停止，不继续入仓或开启下一局。

打点路线按点类型执行：途径点是纯路点，3px 内算路过；箱类点按距离慢步或碎步靠近。当前目标是电子保险箱时，进入目标点 15px 半径后保持 0.08 秒短步。可信提示出现后松键，再按类型交互：电子保险箱执行光圈解锁，机械保险箱长按 F，普通箱子和门点按。每局只执行一条路线。路线结束并完成末尾现场判断后，进入退出结算；执行器不衔接其他路线，也不朝其他出生点移动。导航只按坐标移动，不提供遇敌恢复。

**电梯点。** 电梯点是唯一不按「到达」判定的点：小地图在进电梯时会整块消失，坐标与朝向都读不到，3px 之类的到达判据在电梯口根本不成立。执行分四段，见[电梯进出](navigation.md#电梯进出)。

出生点不在已登记范围内，或该出生点没有开启路线时，走非支持出生点那条退出重开的路：退出本局、返回入口、重新入场，不计成功，也不计入连续失败，也不保存现场截图。出生点识别没有稳定结论时，按失败局收尾，计入连续失败。开启的路线在运行中被发现无效时，任务停止。

寻路卡位、定位失败、局内步骤或操作超时、被敌人击杀、容器恢复失败、装入安全箱无法安全继续（面板状态不明、连续两件物品搬不动），以及搜查或解锁中断，均进入失败收尾。正式应用释放输入、记录原因和截图，再根据新画面退出到仓库。核对安全箱入仓并按开关清理后，正式应用才决定是否重开。全局或同一路线的连续失败达到上限时，应用仍先完成结算，再停在仓库。失败局不计成功。详细规则见[失败重开](settle.md#失败重开)。

| 结算结果或配置 | 计数和后续动作 |
| --- | --- |
| 正常完成局，安全箱有物，已确认入仓并完成清理 | 增加 1 个成功局数，并清零全局和本局路线的连续失败数。清理关闭时，只需完成入仓和结算核验 |
| 失败局，即使安全箱有物，已确认入仓并完成清理 | 不增加成功局数，计入连续失败 |
| 安全箱为空 | 跳过出售，仍核对安全箱为空且容量可读，满仓也允许返回入口；不增加成功局数，连续失败数不变。连续 3 次空箱后停止 |
| 成功次数上限为正数，且已达到上限 | 任务成功结束 |
| 成功次数上限为 0 | 继续执行，仍受失败、异常和连续空箱停止条件限制 |
| 入仓失败、清理失败、再入仓后仍有残留或状态不明 | 停在当前画面，不开始下一局 |

## 配置（`BagelConfig`）

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `difficulty` | `高危` | 挑战难度：`常规`、`困难`、`高危`。推荐装备价值分别为 12000、72100、258000。缺省或无法识别的值按高危。切到困难或常规时，设置页提示改用非高危路线，不自动改开启选择 |
| `max_success_rounds` | 1 | 成功局数上限，范围为 0–1000。0 表示不限成功次数。非支持出生点和失败局不计数 |
| `max_consecutive_failures` | 5 | 连续失败上限，范围为 1–10。全局或同一路线连续失败达到 N 局时停止；成功入仓后清零全局和本局路线的计数，其他路线计数保留。1 表示首次失败结算后停止。旧配置项 `max_failure_retries` 不再读取 |
| `blueprint_priority` | 开 | 蓝图独立为最高入箱分组；蓝图之间按品质比较，同品质不对换。旧配置缺项也开启；仅影响局内入箱 |
| `auto_clean_warehouse` | 开 | 关闭时只入仓，开启时按间隔或满仓/残留规则出售；空箱规则见上文 |
| `sell_interval` | 5 | 本任务非空入仓次数，范围为 1–999，包含失败局带回物资。1 表示每次都卖；正常结束补卖。关闭清理时不出售 |
| `clean_mode` | `default` | `default` 使用上表的两步默认方案。`custom` 按 `clean_steps` 顺序多次出售 |
| `clean_steps` | 空列表 | 自定义出售步骤。每步含 `types` 和 `qualities`，两者都不能空。没有步骤时，自定义清理不能启动 |

默认值用于新配置或缺少对应键的配置，已有显式配置优先。任务配置页位于主窗口内，可以滚动。设置自动保存，并绑定当前账号和应用组。进入页面加载配置时，页面不写回配置。

页面显示累计成功与连续失败两个结束条件，另有挑战难度下拉框。自动出售的间隔、范围和自定义步骤归入同一父卡片；所有步骤下方共用一份总预览。编辑规则与提示条件由 `bagel/gui/setting_interface.py` 实现，实际计数和执行顺序不变。使用说明里的难度和路线提示由 `bagel/usage.py` 维护。

## 执行与输入清理

正式应用和操作基类为每次执行分别包装暂停、恢复回调。执行结束时，清理按以下顺序进行：

1. 停用本次执行的订阅。
2. 等待已开始的回调完成。
3. 从运行总线解绑。

初始化或收尾异常也使用该清理流程，避免上一次执行的回调影响下一次执行。

局内执行器和路线试跑共用输入清理函数。暂停回调释放前进、交互的键盘输入及后台手柄输入，不重置鼠标，也不发送左键松开消息；映射到鼠标的定时输入由原动作自行结束。当前拖拽完成后，框架在下一轮检查暂停或停止状态。恢复后仍先核验原次搬运，不直接重拖。

打点路线执行还有一层自己的输入线程，见[输入线程与动作打断](navigation.md#输入线程与动作打断)。暂停只把前进、后退意图置为松开，不打断即时动作；退出路径调 `shutdown()` 停掉三条通道并显式释放 W、S、F，避免线程残留导致按键一直按着。

执行结束后，业务线程重置持续按键，释放定时前进、交互和鼠标左键；后台再发送左键松开消息。路线编辑器关闭时沿用已有的异步等待线程收尾。暂停请求不代表鼠标已交还，用户应等当前动作结束后再接管；前后台暂停与停止的实机表现尚未验证。

## 功能限制

- 入箱不按物品名称和等级筛选，也不记录按名单收集的进度。
- 收集操作不拾取金币，不将携带货币计入已入仓物资。

## 正式任务的提示

设置文案与运行提示由 `usage.py` 管理。正式应用校验通过后记录配置摘要；收尾结果与停止原因仍由原有操作返回。成功结束的位置来自返回操作的实际状态，未确认时不声称已返回入口。截图接口返回名称，提示层确认文件存在后才展示完整路径。

定位等待通过可选回调向正式应用报告。回调不改变导航的输入、等待时间或失败预算；路线试跑不传入该回调。出售规则、节点状态、计数和重试行为保持原样。

返回入口使用完整入口特征等待。判据、时限和不用全屏稳定检测的理由见[为什么不用全屏稳定检测](settle.md#为什么不用全屏稳定检测)。
