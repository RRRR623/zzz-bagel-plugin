# 路线、出生点与地图

路线文件是打点路线与点位的唯一来源：默认路线随插件发布，自定义路线和开启选择保存在主程序工作目录的 `plugin_data/zzz-bagel-plugin/bagel/`，规则见[贝果路线与出生点](#路线与出生点)。`BagelApp` 用 `BagelRouteWalker` 识别出生点并执行开启的路线，外层应用负责入场、结算、清理和重开。

网页路线编辑器负责录制、试跑、编辑和开启选择，正式执行只读路线文件和开启选择。编辑器说明见[网页路线编辑器](editor.md)。地图资源和坐标规则见[分层小地图说明](#分层小地图)。

## 路线与出生点

本节说明打点路线、出生点和开启选择的数据规则：文件位置、格式、写入保护和开启选择。编辑器操作见[网页路线编辑器](editor.md)。正式运行的出生识别见[出生识别与导航](navigation.md#出生识别与导航)。

### 术语

| 术语 | 含义 |
| --- | --- |
| 出生点 | 入场时角色所在的固定位置。出生点在出生点清单中登记，独立于路线首点：移动路线首点不改变出生点位置 |
| 路线 | 一串有序点位，顺序就是行走顺序。每条路线绑定一个出生点 |
| 默认路线 | 随插件发布的路线。内容只读，可以开启、关闭、复制和试跑 |
| 自定义路线 | 用户新增、录制或复制得到的路线。可以编辑节点、改名和删除 |
| 开启选择 | 每个出生点当前用于正式运行的路线。一个出生点最多开启一条路线，也可以不开启 |

### 文件与标识

| 文件 | 位置 | 内容 |
| --- | --- | --- |
| `bagel/assets/game_data/bagel/spawn_points.yml` | 插件包，只读 | 出生点清单，以及首次使用时开启的默认路线 |
| `bagel/assets/game_data/bagel/routes/<标识>.sample.route.json` | 插件包，只读 | 默认路线 |
| `plugin_data/zzz-bagel-plugin/bagel/routes/custom_<标识>.route.json` | 主程序工作目录 | 自定义路线 |
| `plugin_data/zzz-bagel-plugin/bagel/route_settings.yml` | 主程序工作目录 | 开启选择 |

插件更新会整体替换插件目录，所以用户写入的文件只放在主程序工作目录。

#### 出生点清单

每个出生点登记以下字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定标识。路线和开启选择用它引用出生点 |
| `name` | 显示名称 |
| `layer` | 完整分层名，如 `雅努斯幻境/Custom` |
| `x`、`y` | 全局坐标，坐标体系见[分层小地图说明](#分层小地图) |
| `radius` | 识别半径，单位为地图像素。定位结果与出生点的距离不超过该值，才算命中 |
| `initial_route` | 首次使用时开启的默认路线标识。`null` 表示首次使用时不开启路线 |

当前清单登记了雅努斯幻境的 5 个出生点。识别半径均为 100 地图像素：

| 标识 | 显示名称 | 全局坐标 | 首次使用时开启 |
| --- | --- | --- | --- |
| `janus_video_store` | 录像店 | `(822,348)` | 录像店-默认 |
| `janus_worksite_station` | 白鸽工地站 | `(341,432)` | 白鸽工地站-默认 |
| `janus_south_station` | 六昏街南站 | `(1002,466)` | 六昏街南站-默认 |
| `janus_construction` | 改建工程区 | `(602,30)` | 不开启 |
| `janus_worksite_depths` | 工地深处 | `(255,829)` | 不开启，没有默认路线 |

坐标取自录像定位。清单只包含已观察到的出生位置，不能证明出生点已经全部登记。城郊幻境没有登记出生点。正式应用的入场地图范围不因编辑器显示城郊地图而改变。

#### 路线文件

路线文件使用 JSON，格式版本为 2：

```json
{
  "version": 2,
  "route_id": "录像店-默认",
  "name": "录像店-默认",
  "spawn_id": "janus_video_store",
  "started_at": "2026-10-25T23:34:41+08:00",
  "ended_at": "2026-10-25T23:35:16+08:00",
  "points": [
    {"x": 830, "y": 351, "layer": "雅努斯幻境/Custom", "kind": "beacon"}
  ]
}
```

- `route_id` 创建后不变，并与文件名主干一致。文件名与标识不一致时，文件按损坏处理。
- `name` 是显示名称。改名只修改 `name`，不修改标识和文件名，所以开启选择不受改名影响。全部路线的显示名称不能重名。
- `spawn_id` 是绑定的出生点。路线创建后，编辑器不提供更换出生点的操作。
- 路线文件不保存开关状态。路线是否开启由开启选择决定。
- 点位字段与类型见[路线文件中的点](editor.md#路线文件中的点)。

来源由文件位置决定：`*.sample.route.json` 是默认路线，其余 `*.route.json` 是自定义路线。程序不接受网页声明的来源。自定义路线标识必须符合 `custom_` 加小写字母、数字或下划线的形式。默认路线和自定义路线分别加载，不存在同名文件覆盖默认路线的规则。

#### 路线能否开始

路线的首点必须同时满足以下条件，路线才能从出生点开始执行：

1. 首点是途径点。
2. 首点与出生点在同一完整分层。
3. 首点与出生点的距离不超过该出生点的识别半径。

开启路线、保存自定义路线和正式运行时都检查这些条件。不满足时，开启和保存被拒绝，正式运行拒绝开始。

### 开启选择

开启选择为每个出生点保存一个路线引用，或保存 `null` 表示不开启：

```yaml
version: 1
active_routes:
  janus_video_store:
    source: default
    route_id: 录像店-默认
  janus_construction: null
```

每个出生点只有一个引用，所以同一出生点不会同时开启两条路线。切换路线时，程序更新该出生点的引用，再一次写入整个文件。

| 条件 | 处理 |
| --- | --- |
| 配置文件不存在 | 按出生点清单的 `initial_route` 初始化。只引用存在且绑定该出生点的默认路线 |
| 配置文件存在，某个已登记出生点没有记录 | 该出生点按不开启处理。新发布的默认路线不改变用户的选择 |
| 配置文件存在，但记录了未登记的出生点 | 忽略该记录，编辑器显示提示 |
| 配置文件损坏 | 报告错误，不重新初始化。正式任务拒绝开始，编辑器的写入操作报告同一错误 |
| 引用的路线不存在、损坏、绑定其他出生点或不能开始 | 该选择标记为无效，不自动换成其他路线。正式任务拒绝开始 |
| 删除开启中的自定义路线 | 先把该出生点改为不开启并写入，再删除文件。不自动开启其他路线 |

路线与开启选择不区分账号，所有账号共用。

### 写入规则

所有写入都经过 `BagelRouteStore`。编辑器、录制器和执行器不自行拼接路径。

- 默认路线只读。保存、改名和删除只接受自定义路线标识；默认路线标识一律拒绝。该检查在 Python 侧执行，不依赖网页隐藏按钮。
- 新增路线时，首点为出生点坐标上的途径点。新增和录制的路线可以选择创建后开启；默认不开启。
- 复制路线生成新的自定义路线：使用新标识和新名称，保留出生点和全部节点参数，初始不开启。复制不改变源路线和当前开启的路线。
- 每次写入先写同目录临时文件，读回核对后再替换目标文件。核对失败时，原文件保持不变。

### 模块分工

| 模块 | 职责 |
| --- | --- |
| `bagel/route/route_model.py` | 出生点、路线、点、路线引用的数据定义与格式转换，以及路线开始条件检查。不依赖 Qt 或录制器 |
| `bagel/route/route_store.py` | 出生点清单与路线文件加载、默认路线写入保护、自定义路线保存、复制、改名、删除、开启选择 |
| `bagel/route/spawn.py` | 用一次定位结果匹配出生点，区分唯一命中、未命中和多个命中。不截图，不读写配置 |
| `bagel/route/route_recorder.py` | 游戏内录制。首个点必须满足所选出生点的开始条件，停止后保存为自定义路线 |
| `bagel/route/route_walker.py` | 识别出生点，执行开启的路线或试跑指定的路线 |

### 已知限制

- 出生识别半径 100 地图像素沿用旧锚点距离，尚未针对出生点识别做实机标定。
- 工地深处没有默认路线。抽到该出生点时，正式运行按没有开启路线处理。
- 出生点清单只能通过修改 `spawn_points.yml` 维护，编辑器不提供新增或移动出生点的操作。

## 分层小地图

### 用途与坐标

出生识别、路线执行、网页编辑器共用同一套分层底图。应用流程见[流程总览](overview.md)，编辑操作见[网页路线编辑器](editor.md)。

资源位于 `bagel/assets/game_data/map_locator/`，共 22 层：雅努斯幻境 10 层，城郊幻境 12 层。

| 文件 | 用途 |
| --- | --- |
| `layers.json` | 分层清单：每层的 `map_id`、`name`、`image`、`origin` |
| `layers/<地图>/*.png` | 各层底图，透明区表示无有效来源 |

每层的完整分层名为 `map_id/name`，例如 `雅努斯幻境/Custom1_1`。路线点的 `layer` 字段存完整分层名。层内匹配出圆心后加 `origin`，得到跨层可比的全局坐标。路线坐标一律取整后的全局坐标。

### 实现约束

- 纹理匹配：小地图只取圆形有效区（半径 88），高通提取纹理；底图透明区填黑后同样高通；比较归一化相关系数，不用颜色或朝向约束。
- 模板匹配返回整数像素，定位结果为整数。若距离出现 0.5px 这类小数，说明路线文件里的点坐标带小数，需要规范化为整数，不是定位误差。
- 三档搜索：先在当前层附近找（门槛 0.18）；当前层连续命中失败时，在 1 秒内只比较同地图且与上一帧位置相交的层；丢失满 1 秒后才搜索全部层，跨层门槛更严（0.22）。零方差窗口直接拒绝，不给假高分。
- 空白或全遮挡帧直接返回空，由外层停步等待；连续 10 秒定位失败才判失败，给全层搜索留时间。
- 图像匹配不发送游戏输入。外层操作负责停步、等待和松键。

### 资源与定位

`layers.json` 每层四个字段：`map_id`（所属地图）、`name`（层名）、`image`（相对路径）、`origin`（该层在所属地图原画布上的偏移）。

`load_map_locators` 按清单顺序加载各层图像与偏移；`MultiMapLocator.locate` 按上节三档顺序搜索，返回命中的层、评分与全局坐标圆心。

网页编辑器按 `origin` 把同一地图的各层拼成整图显示，反相成浅底深线，仅用于显示，不参与定位。

### 出生位置资料

出生点清单不表示已经完整。出生点登记和路线开启规则见[贝果路线与出生点](#路线与出生点)。

### 来源与限制

当前分层底图的采集过程未在本文归档，不能按原过程重建。归档定位样本可用于核对识别结果，不能替代整张底图的来源记录。

离线测试通过不能代替真机验收。重复纹理和累计漂移仍需人工核对。

## C 路线：单廊双容器

路线文件为 [六昏街南站-默认.sample.route.json](../bagel/assets/game_data/bagel/routes/六昏街南站-默认.sample.route.json)，绑定出生点「六昏街南站」，属于 `雅努斯幻境/Custom`。它保留旧 C 路线的顺序：从长廊出生点出发，搜查机械保险箱，沿西侧道路绕至电子保险箱。

该路线使用当前打点执行器。开箱、收集和关闭面板按点类型执行，正常退出由正式应用负责，见[流程总览](overview.md)。

### 坐标转换依据

旧 C 路线使用以参考出生画面为基准的相对坐标，当前路线使用分层底图的全局坐标。原转换的前九点按下式转换，电子箱目标按上节与既有路线统一。转换先读取旧底图的 `origin_xy=(-165,-140)`，得到旧底图像素位置 `(u,v)=(旧x+165,旧y+140)`，再映射到当前 `Custom` 层，最后取整：

```text
新x = 0.9982797077 × u - 0.0107407598 × v + 741.0870854
新y = 0.0107407598 × u + 0.9982797077 × v + 224.4223300
```

矩阵由两份底图的局部图像特征匹配和一致性筛选得到，保留 42 对匹配点，映射误差中位数约 1.02 像素。该值描述底图之间的几何对应，不是实机定位误差或路线通过率。

### 来源与限制

- 旧路线和地图来源：内置版本 `janus_high_c` 的 `flow.yml`、`map.yml`、`map.png`。
- 当前底图：[Custom.png](../bagel/assets/game_data/map_locator/layers/janus/Custom.png)，层原点为 `(0,0)`。
- 原底图的建图原始输入未完整归档，不能仅凭历史元数据重建旧底图。
- 坐标换算不证明实机可通行。出生锚定、长廊接近、机械箱交互及电子箱站位仍需分别核对；其它路线结束后如何接入该起点也不能由底图匹配保证。
